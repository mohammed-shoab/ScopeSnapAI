## Overall risk rating: **CRITICAL — SYSTEM-WIDE**

The v1 audit found marketing-page issues. **The v2 deep audit finds the same issues embedded 3-4 layers deeper** — in the LLM system prompts, database column names, API response fields, PDF template, homeowner emails, and event tracking names. **Fixing the marketing pages alone would not resolve the legal exposure.**

**The single-line summary:** SnapAI's code identifies itself as *"an expert HVAC fault diagnosis system"* — literally in the LLM system prompt — and that framing propagates into every response field, every database row, every homeowner report, every email, and every audit trail event.

**Cascading effect for litigation:** When plaintiff's counsel subpoenas SnapAI's logs, they will find event names like `diagnostic_resolved`, `diagnosis_correct`, database tables named `diagnostic_sessions`, API response fields named `diagnosed_card_id`, and LLM prompts that literally instruct the AI: *"You are an expert HVAC fault diagnosis system."* Every one of these is a discoverable admission that SnapAI positioned itself as the diagnostic authority. No ToS applied after the fact can override the design evidence.

## New CRITICAL findings (in addition to v1 findings C1-C4)

### C5. LLM system prompt frames the AI as the "diagnosis system" — highest liability finding in the entire audit

**File:** `scopesnap-api/prompts/cascade_prompts.py`

Verbatim, lines 47 and 79 (both LLM prompt templates):

> `"You are an expert HVAC fault diagnosis system acting as a senior reviewer."`

Response JSON schema field names generated by the LLM (also in the prompt):

- `confirmed_fault` — the AI's diagnostic conclusion
- `sensor_diagnosis_correct` — the AI grading its own diagnosis
- `visual_findings_correct`
- `explanation` — "plain English explanation for the technician"
- `recommendation` — "specific next steps for the technician"

**Legal exposure:** This is worse than any marketing copy. In discovery, plaintiff counsel obtains the exact prompt SnapAI sends to the LLM. That prompt literally says "You are an expert HVAC fault diagnosis system." Every LLM response is generated *believing* it is the diagnosis system. This is dispositive evidence of design intent that cannot be walked back.

Compare to the correct framing:
> `"You are a decision-support assistant for licensed HVAC technicians. Provide preliminary findings for the technician's independent verification. Never state a definitive diagnosis. Always frame outputs as recommendations subject to professional review."`

**Fix (P0):** Rewrite both `TRACK_A_CONFLICT_PROMPT` and `TRACK_B_UNCERTAIN_PROMPT` in `cascade_prompts.py`:
- Change role from "expert HVAC fault diagnosis system" → "decision-support assistant for licensed HVAC technicians"
- Rename response field `confirmed_fault` → `suggested_finding_for_review`
- Rename `sensor_diagnosis_correct` → `sensor_reading_appears_consistent`
- Rename `visual_findings_correct` → `visual_scan_supports_finding`
- Add mandatory prompt line: *"Never present findings as certified diagnoses. Every output is preliminary and requires technician verification."*
- Bump `PROMPT_VERSION` and log the change in `PROMPT_CHANGELOG` (already exists in `equipment_analysis.py`)

**Priority:** Immediate. This prompt is the deepest source-of-truth for how SnapAI conceives of itself.

### C6. Homeowner-facing LLM prompt uses "doctor visit summary" and "honest" language

**File:** `scopesnap-api/prompts/homeowner_narrative.py`

Verbatim, lines 12-22:

> `"You are writing for a homeowner who knows nothing about HVAC. Be warm, clear, and honest. No jargon. No scare tactics. No sales pressure."`

> `"1. What the equipment is and its general health (think 'doctor visit summary')"`

Example good output written into the prompt (line 24-26):

> `"Your Carrier AC is 9 years old and in fair condition. The indoor coil has corrosion that's reducing your cooling efficiency by about 15-20% — worth addressing before summer."`

**Legal exposure — three vectors:**

1. **"Honest" superlative propagation** — the word "honest" in the LLM instruction bleeds into every homeowner output. DTPA §17.46 vector (unsubstantiated superlative). Comment from v1 audit finding H2 escalates: this isn't just marketing copy, it's baked into the AI's generation logic.

2. **"Doctor visit summary" framing** — Medical analogy in a prompt to a homeowner escalates the diagnostic-authority framing. If a homeowner ever sues over reliance on this text, "doctor visit summary" language in the prompt is Exhibit A that SnapAI positioned itself as a medical-analog diagnostic authority.

3. **Specific quantified health claims in the example** — "reducing your cooling efficiency by about 15-20%" is a specific engineering-performance claim to a consumer that requires substantiation. If false in the specific case, DTPA violation. If not substantiated in general, FTC deceptive practices vector.

**Fix (P0):** Rewrite `HOMEOWNER_NARRATIVE_PROMPT`:

```python
HOMEOWNER_NARRATIVE_PROMPT = """
You are writing a plain-language summary for a homeowner. This summary supports
the licensed HVAC contractor's professional recommendations — it does not replace
them.

Never present findings as certified diagnoses. Never use medical analogies.
Never make specific efficiency, cost, or life-remaining claims. Always attribute
recommendations to the licensed contractor performing the work.

Equipment: {brand} {model}, installed {install_year} ({age} years old).
Preliminary contractor assessment: {overall_condition}.
Preliminary items your contractor flagged for review: {issues_plain_english}

Write exactly 2 sentences:
1. What the equipment is and what your contractor observed (do not state a
   definitive condition — describe what was observed for review).
2. What your contractor recommends you discuss with them next.

Under 40 words. Attribute all recommendations to "your contractor." Never state
that SnapAI diagnosed or determined anything.
"""
```

**Priority:** Immediate. Every homeowner report currently in the field was generated by an LLM told to write like a doctor visit summary.

**Fix (P0):** Add mandatory disclaimer block to `contractor_estimate.html` above signature line:

```html
  judgment of {{ company_name }} (License #{{ company_license }}), a licensed
  HVAC contractor. SnapAI is a decision-support tool used by {{ company_name }};
  it does not perform diagnoses. Findings and recommendations require independent

  request a full safety inspection separately. This estimate is not a certification

```

**Priority:** Immediate. Every PDF generated between now and fix carries no disclaimer.

## Bryan Orr — HVAC domain angle on v2 findings

Two things I want to emphasize from a field perspective:

1. **The LLM prompt fix (C5) is the single most impactful change.** Every fault card resolution, every escalate message, every homeowner narrative — they all trace back to those two prompt files. Fix them and the downstream cleanup gets 60-70% easier. Miss them and you're chasing strings through every component.

Change the enum values to trade-authentic language and both problems fix at once.

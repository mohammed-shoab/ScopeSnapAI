3. DATA ARCHITECTURE + SEED PLAN (Gate 4)
================================================================
Existing pattern (verified live): diagnostic_questions holds branch_logic_jsonb (branching in DB);
reading_inputs does deterministic numeric classification; operating_targets holds PSI thresholds only.

3a. NEW THRESHOLD DATA (author as SQL seeds, cite source + confidence per row):
  - superheat_subcool_targets  (by refrigerant x metering type x ambient)   -> #8/#15b/c/#10c discrimination
  - static_pressure_targets    (0.5 in.w.c. budget + 4-point drop rules)     -> #20 / Airflow Assessment
  - delta_t_targets            (delta-T vs indoor RH)                        -> #20 / #22
  - latent_targets             (indoor RH 45-55, wet-bulb/grain depression)  -> #22
  - sizing_rules               (sq-ft/ton by climate, run-time %, cycle-rate, Manual J inputs) -> #24
  - compressor_test_thresholds (winding-to-ground R, LRA/RLA, compression ratio) -> #10a-e
  Research sources (Will/Joe, source-check every number): ASHRAE Fundamentals, ACCA Manual J/S/D,
  manufacturer charging charts (Carrier/Trane/Goodman), Emerson/Copeland compressor bulletins, NIST FDD,
  ENERGY STAR field studies.

3b. NEW FAULT CARDS: add #20/#22/#23/#24 (+ 10a-e, 15b-d as family members) to a fault_cards seed,
  structure per _WS_A_SQL_SEED/seed_02_fault_cards.sql PLUS the newer jsonb cols on the live table
  (action_steps, alternative_cards, climate_notes_us). #24/#10a/b/c carry replacement TCO in card_tco_data.

3c. NEW QUESTIONS: add to _WS_A3_SQL_SEED/diagnostic_questions_seed.sql (re-seedable via DELETE-then-insert,
  generated by gen_seed_sql.py from SnapAI_Phase3_Cowork_Instructions.md). Use existing branch_logic_jsonb
  grammar (next_step_id / resolve_card / phase_2_gate / escalate / finding). Numeric gates = reading type
  with reading_spec compare_to + tolerance = deterministic, no LLM.

3d. SEED/DEPLOY REALITY: diagnostic_questions + fault_cards are seeded MANUALLY per-environment via the
  Supabase SQL editor (not git-promoted). Code goes staging-first (DEC-070); this reference DATA is seeded
  directly. See open decision 6 on staging parity.

4. VALIDATION LOOP (Gate 1)
================================================================
Seed thresholds from US priors (3a) -> tag each card high-freq vs tail -> ship (high-freq full confidence,
tail LOW) -> every diagnosis writes readings to reading_inputs + outcome to card_feedback/diagnosis_feedback
(both tables already exist) -> monthly compare predicted vs confirmed -> recalibrate thresholds from prior to
field-calibrated -> a card graduates LOW->HIGH at >=85% confirmed match over N>=30.
